A PRACTICAL ROADMAP

From demo to
data you can trust.

The analytics charts are still synthetic. The audit is an imported, dated snapshot—not a live source. Follow this plan before replacing either with real figures.

!

Start with safety, not integrations. Do not publish prospect records, financial information, report tokens, API keys or raw exports to this public site or repository. Data collection and outreach require your approval.

01 · Establish the source of truth

Choose one owner, definition and refresh schedule for each number. Start with RankOps, then repeat for the other two properties. Mark missing data Unavailable, not zero. Keep the audit’s October 26 snapshot separate from newly measured facts.

02 · Make a small private baseline

  1. Pick a 30-day window and export one property at a time. Record the source, export time, timezone, filter definitions and any gaps. Do not assume an audit claim is current until you check it at the source.
  2. Keep source receipts in a private, access-controlled folder. For each metric retain property_id, date_or_window, metric, value, source, observed_at, timezone and definition_version; add real dimensions only where the source supports them.
  3. Manually reconcile one daily number, one 30-day total and one page/channel breakdown with each original dashboard. Identify test leads and duplicates. Mark gaps and conflicting sources as unverified.
  4. Publish no real figures until the definitions, privacy review and reconciliation are approved. The existing charts stay labeled demo until then.

03 · Rebuild the analytics layer, not just the data file

The current chart code is a simulation. It multiplies overall channel, device and engine shares together and estimates filtered counts; it sums daily visitor values and traffic-weights a visibility score. It cannot faithfully answer real cross-filter queries or deduplicate people across days and properties. Swapping a JSON file would produce plausible but potentially false numbers.

  • Replace demo aggregation with actual source-provided counts or a properly modeled aggregate dataset. Support only combinations your source can measure; otherwise disable the filter or show Unavailable.
  • Choose sessions, page views or true range-deduplicated users; label them accurately. Never add daily unique-user totals or unique counts across properties as if they were unique for the entire window.
  • Keep AI referrals, AI-answer mentions, map scores and search clicks distinct. Use the appropriate denominator, show the number of checks, prompt set, engine and last observation, and do not invent per-page or device attribution.
  • Remove demo-specific assumptions: fixed sample dates, seeded page-channel weights, synthesized trends, estimated splits and forced zeros. Handle missing dates, source outages, refresh delays and previous-period comparisons explicitly.

04 · Connect safely, then automate

  1. Choose whether the resulting analytics are public or owner-only. For private business data, use an authenticated backend or an owner-only local import; hiding a public URL or adding a browser-side password is not security.
  2. For online access, protect the entire data API with Cloudflare Access (or equivalent) and validate signed identity tokens server-side on every request. Configure least-privilege, read-only service accounts and restrict access to your identity; fail closed when verification fails.
  3. Store credentials and refresh tokens in the provider’s secret manager, never in browser JavaScript, Git, a public Pages asset, URL, log or this audit file. Return only authorized, minimized aggregates; use encryption, retention rules and private backups.
  4. Run read-only scheduled ingestion with logging, retry limits, idempotency and an explicit spending cap. Nothing should send outreach, alter records or pay a bill. Record last_successful_sync, partial failures and source versions.

05 · Validate and release

  • Test known totals, zero versus missing data, duplicate leads, source timezones, filtering, pagination and access denial. Reconcile each property and metric with a dated source receipt.
  • Test empty, delayed and failed sources; stale data must say when it was last refreshed. Test that unauthorized users cannot reach APIs or private exports, and that no credentials or identifiers are in the built site or Git history.
  • Review a private preview, get your approval, then deploy. Preserve the previous version and a rollback path. Reconcile weekly and review data definitions when sources change.

Nothing is connected or synced by this guide. For developer-level migration notes, see the repository README.
